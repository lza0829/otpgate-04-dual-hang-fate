# 验码渠（Otpgate）

骨架：通道注册 → 选路投递 → 失败熔断切备通道 → 送达回执对账

- 前端 http://127.0.0.1:6900
- API http://127.0.0.1:11900
- 数据库环境变量 `OTPGATE_DB`（容器内默认 `/data/otpgate.db`）

```bash
docker compose up -d --build
```

## 双挂命运（全站唯一架构）

架构只留一臂：**双挂必须硬拒**。主路、备路皆不可用（熔断中/停用任意组合：
皆熔断、一熔一停、皆停用）时，投递整笔失败，没有第二结局。

- 验码单不进入「投递中」，直接落终态「双挂拒投」，永不送达；
- 每个通道各留一张「拒投」回执，熔断事件留「双挂硬拒」动作，事件痕同事务留痕；
- 路况双挂桶、轧差双挂分桶、事件痕、启停灯、投递探针与终态同刷，
  轧差三项差异（双挂回执差/双挂事件差/送达与回执差）恒为 0；
- 硬投一臂已砍：全站不产生任何硬投标（`硬投标` 恒为 `null`）；
  旧渠规项「允许双挂硬投」废止为只读遗留项，拨任何值都不参与判定；
- 单路熔断切备另立：只有一路不可用而另一路启用时，走切备/改道，不触发双挂。

所有写口（创建、投递、失败熔断、回执、渠规翻转、通道启停）共用
`app/services/dispatch.py` 的同一个 `evaluate` 判定，并统一走
`BEGIN IMMEDIATE` 写锁串行收口；读侧 `/api/投递探针` 与写侧同源，可随时重放。
双挂硬拒在事务提交后才转 HTTP 409，拒投事实不会随异常回滚。
